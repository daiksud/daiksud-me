## Feature: 見出しを使って記事内を移動する

### Scenario: TOC-01 記事の構成を見渡す

- Given: 記事本文にh2またはh3の見出しが2件以上ある
- When: 読者が記事を開く
- Then: 画面幅1000px以上では、記事の右側に「この記事の目次」という独立したペインが表示される
- And: 記事ペインと目次ペインは、ペイン間の余白も含めて最大1200pxの幅でメイン領域の中央に配置する
- And: 1000px未満では、ヘッダーと本文の間に「この記事の目次」を開閉できる形で表示する
- And: 目次のナビゲーションには「目次」という読み上げ用ラベルを付ける
- And: 一覧は文書内の順序に従い、h3の項目を視覚的に区別する

### Scenario: TOC-02 役立つ場合にだけ記事の目次を表示する

- Given: プロフィールを含む、共通の記事レイアウトを使う任意の記事がある
- When: 本文の対象となる見出しが0件または1件である
- Then: 目次も空の囲み要素も表示しない
- And: 記事タイトルとh4〜h6の見出しは目次の項目に含めない

### Scenario: TOC-03 表示された見出しの識別情報を維持する

- Given: 日本語、重複、強調、コード、エスケープされたテキストを含む見出しがある
- When: 目次を表示する
- Then: 読みやすい表示名はエスケープされたテキストで、リンク先は対応する表示済みの見出しIDである
- And: 見出しIDの生成元は既存のMarkdownレンダラーだけとする

### Scenario: TOC-04 デスクトップとモバイルでリンクをたどる

- Given: JavaScriptが無効で、記事に重複した見出しと長い表示名がある
- When: 読者がリンクをたどるか、キーボードでリンクを選択する
- Then: 目的の節に移動し、キーボードのフォーカスが見える
- And: 狭い画面の目次もJavaScriptなしで開閉できる
- And: 目次が横方向にはみ出さず、配置されたペインの幅に収まる

### Scenario: TOC-05 記事を読み進めながら右側の目次を使う

- Given: 画面幅1000px以上で、目次を持つ長い記事を表示している
- When: 読者が記事をスクロールする
- Then: 目次は記事の右側の独立したペインでスクロールに追従する
- And: 記事タイトルと本文は目次とは別の記事ペインで、共通の左右余白を除いた幅を使う
- And: 目次が画面より長い場合はペイン内をスクロールでき、最後のリンクも操作できる

### 検証範囲

専用のフィクスチャのビルドテストとPlaywrightの検証でTOC-01〜TOC-05を確認します。既存の読者の操作で、メタデータ、タグ、コンテンツ、ホームのナビゲーション、ルート、ホスティング環境のnoindexポリシーを保護します。現在の節の追跡、独自のスクリプト、記事ごとの設定は、この機能の範囲外です。
